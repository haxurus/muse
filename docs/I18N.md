# Bot languages (i18n)

Muse answers in **English by default**. Each guild can switch the bot's messages to **Italian**. Slash command names stay English everywhere; their descriptions are also shown in Italian to Discord users whose client language is Italian.

## The `locale` guild setting

| Value | Language |
| --- | --- |
| `en` | English (default for every guild, including existing ones after the migration) |
| `it` | Italian |

- Stored in `Setting.locale` (`schema.prisma`), added by migration `20261006120000_add_guild_locale` (`ALTER TABLE "Setting" ADD COLUMN "locale" TEXT NOT NULL DEFAULT 'en'`). New guild rows get `en` from the column default.
- Values are exact and case-sensitive: anything other than `en` or `it` (for example `IT`, `fr` or a number) is rejected.
- Each bot (worker) has its own database, so the language is per guild **and per bot**, like the other settings.

## Where to set it

- **Dashboard**: the "Bot language" / "Lingua del bot" field in the guild settings. It sends `{"locale": "it"}` (or `"en"`) in the settings `PATCH`, exactly like the other fields.
- **Discord**: `/config set-language language:<English|Italiano>` (needs Manage Server, like every `/config` subcommand). The confirmation is sent in the new language. `/config get` shows the current value.
- **Control API**: `PATCH /v1/guilds/:guildId/settings` on a worker, or the orchestrator's `PATCH /v1/guilds/:guildId/workers/settings` with `"settings": {"locale": "it"}`. `GET .../settings` returns `locale`. See `ORCHESTRATOR.md`.

## What is translated

Everything the bot shows to Discord users: command replies and follow-ups, error replies (including the generic "something went wrong" text and the blocked-user refusal), queue / now-playing embeds, the automatic next-song announcement, `/config get`, the orchestrated playback pilot messages, and the "Bot started" / test embeds in the bot status channel (`status*` keys, in the locale of the channel's server for that bot; see `SUPER_CONSOLE.md`).

- The owner welcome DM is sent when the bot joins a guild, before any setting exists: it uses the guild's Discord `preferredLocale` (`it*` gives Italian, anything else English) and tells Italian owners how to switch with `/config set-language`.
- Logs, control/orchestrator API errors and dashboard-facing JSON stay English.
- Messages from third parties (for example raw provider errors that are shown verbatim) are not translated.

## How it works

- `src/i18n/en.ts` holds the English dictionary (`EN_MESSAGES`) and defines the message keys (`MessageKey`).
- `src/i18n/it.ts` holds the Italian dictionary, typed as `Record<MessageKey, string>`: a missing or extra key fails `tsc`, and `tests/i18n.test.ts` also checks keys and `{placeholders}` at runtime.
- `src/i18n/index.ts` exports:
  - `t(locale, key, vars?)`: translation with `{name}` interpolation; unknown locales and missing keys fall back to English.
  - `UserError(key, vars?)`: an intentional user-facing error. Its `message` stays English (logs and existing checks on `error.message` keep working); the interaction handler renders it with `error.localize(locale)`.
  - `localizeEnglishMessage(locale, message)`: translates a fixed English string that matches a dictionary entry (used for plain `Error`s from the player and for messages relayed through the playback hops, which stay English on the wire).
  - `localeOf(settings)`, `normalizeLocale`, `isLocale`, `localeFromDiscord`.
- `src/i18n/guild-locale.ts` exports `getGuildLocale(guildId)`, which reads the guild's settings row and falls back to English on any failure. Code that already has the settings row loaded uses `localeOf(settings)` instead of a second read.

## Adding a language

1. Add the code to `SUPPORTED_LOCALES` in `src/i18n/index.ts` (use the Discord locale code when it is a plain language, e.g. `de`, `fr`).
2. Create `src/i18n/<code>.ts` exporting a `MessageDictionary` with every key, and register it in `DICTIONARIES`.
3. Add the choice to `/config set-language` (`src/commands/config.ts`) and, for slash command descriptions, a `<code>` entry next to each `setDescriptionLocalizations({it: ...})` (Discord limit: 100 characters).
4. If needed, extend `localeFromDiscord` for the welcome DM.
5. Update the dashboard language field, this document and the tests (`tests/i18n*.test.ts`).

The settings validation accepts exactly `SUPPORTED_LOCALES`, so no migration is needed for a new language.
